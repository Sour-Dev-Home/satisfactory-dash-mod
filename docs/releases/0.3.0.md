# satis-dash agent 0.3.0

**Linux servers are supported.** This release builds the mod for both Windows and Linux dedicated servers and ships them
in one multi-target archive. What the mod reads, and how it talks to the dashboard, are unchanged from 0.2.0.

## Install

You need **SML 3.12.0 or later (3.x)** on the server; the mod has no other dependency.

Where to get SML: the Satisfactory Mod Manager (SMM) installs it for you. For a manual install, take it from SML's page
on ficsit.app (https://ficsit.app/mod/SML).

The release has three files:
- `SatisDashAgent.zip`: the multi-target archive, with a `WindowsServer/` and a `LinuxServer/` folder.
- `SatisDashAgent-WindowsServer.zip` and `SatisDashAgent-LinuxServer.zip`: one platform each.

To install with pairing (the main way, and the one SMM users take):
1. Install SML and the mod on the server. SMM does both; for a manual install, put your platform's zip (or its folder
   from `SatisDashAgent.zip`) in `FactoryGame/Mods/SatisDashAgent/`, so the folder holds `SatisDashAgent.uplugin`
   directly.
2. Start the server. The mod logs a line like
   `Pairing code ABCD-EFGH-JKLM: sign in at https://satis-manager.com/pair and enter it (expires in 15 minutes)`.
   Read it in the server console or in `FactoryGame.log`. In the game's chat it shows only when you are the only player
   online.
3. Sign in at https://satis-manager.com/pair, enter the code and confirm the server's name.
4. The mod logs "Paired with the dashboard; reporting to the backend" and saves its credential in
   `FactoryGame/Saved/SatisDash/credential.json`. No file edits.

If the code expires, join the server or restart it to get a new one.

Advanced: the config-file code. To enrol without pairing:
1. Start the server once. The mod writes `FactoryGame/Configs/SatisDashAgent.cfg` with its defaults.
2. Create an enrolment code in the dashboard, put it in `enrollmentCode` in that file, and restart the server. The mod
   enrols, blanks the code and saves its credential. A code in the file always wins over pairing.

## If you are upgrading from 0.2.0

- Replace the mod's folder with the new one. **No re-enrolment is needed**: the config and credential stay where they are.

## Platforms

- **Windows dedicated server.**
- **Linux dedicated server (x86-64).** Built with UE 5.6's Linux cross-toolchain (`v25_clang-18.1.0-rockylinux8`) and
  tested on the Linux server in a Debian container.

## Linux evidence

Each run records `serverHost`, so a Linux pass is never read as a Windows one.

- **http-probe** 42331856203 and **enrol** 42340205949: pass.
- **tick-cost-native** 42402469440 and 42526743569 (PC idle): pass.
  - Tick 29.925 without the mod and with it.
  - Longest step 1.14 ms against the 2 ms ceiling.
  - Memory 6.2 MB above the baseline (limit 100).
- **soak-native, 4 hours,** 42530069076: accepted by owner ruling (2026-11-08).
  - Every soak condition passed: every reader kept its cadence, no Error line, memory +16.8 MB over 4 hours, and the
    end-of-day leak rule passed.
  - The one failure was two Buildables steps (3.54 ms and 2.08 ms) during a 3-minute slowdown of the whole host PC.
    In that window every reader did the same work 30 to 50 times slower and the game's own tick dipped. Docker's Linux
    VM can't tell such a pause from work, because the WSL2 kernel has no steal-time accounting.
- An earlier 16-hour Linux soak (42408741679) failed three checks, and the harness was fixed for each:
  - S12 couldn't name a load-balanced address. The game's own `api.ipify.org` lookup now has DNS names on Linux.
  - Steps were slow during host load. They didn't recur with the PC idle.
  - The last-5-minutes leak window landed on a ~27 MB swing that the baseline shows too. A code review found nothing in
    the mod that grows with uptime.

Windows keeps 0.2.0's evidence, plus **http-probe** 42335642923 and **enrol** 42341193571 (2026-11-07).

## Changes since 0.2.0

- **Device-code pairing (ADR-0051 §1).** The server prints a code and you enter it on the dashboard. The code shows in
  the console and the log, and in the game's chat only when you are the only player online. The config-file code still
  works.
- **Linux server build.** Two fixes that only the Linux compiler caught: an out-of-order initialiser list
  (`SnapshotAssembler.h`), and a missing `CoreOnline` module dependency in `SatisDashGame`.
- **Linux step diagnostics.** With `stepDiagnostics` on (off by default), the Linux build reports the thread's CPU
  nanoseconds (`clock_gettime(CLOCK_THREAD_CPUTIME_ID)`), as Windows reports thread cycles.
- **Packaging.** Alpakit's merged multi-target archive (`-merge`) is the release file, with the per-platform zips next
  to it.
